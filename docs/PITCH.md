# Eight-slide pitch and demo script

This is a content template, not a finished slide deck. Complete it after the assigned theme and real evidence are available. The PDF recommends five to ten slides and requires problem, solution, AI implementation, architecture and potential impact.

| Slide | Main point | Evidence |
|---|---|---|
| 1 | One person struggles with one specific task | Consented quote or sourced example; assigned theme |
| 2 | The current workaround has a measurable cost | Observed time/error count; do not invent statistics |
| 3 | Show the product's transformation | Actual input and actual useful output |
| 4 | Live demonstration | Real phone, genuine model call, inspect/correct, action |
| 5 | Explain why AI is necessary | Baseline comparison, model role, source/validation method |
| 6 | Architecture and reliability | Data flow, App Check, failure handling, real latency |
| 7 | Results, limitations and sustainable operation | Sample size, measured metric, cost/task, operational owner |
| 8 | Distinction and next step | Alternatives, theme relevance, realistic pilot request |

## A 90-second demo segment

This segment is a rehearsal target, not the official pitch duration.

0–15s: "This is [user]. Today they need to [task], but [specific barrier]."

15–30s: Open the actual input on the phone. Explain permission and origin briefly.

30–55s: Run the real AI task. Explain what the model interprets while it loads.

55–75s: Inspect the output and its supporting evidence. Show one correction or uncertainty behavior.

75–90s: Complete the user's next step and state the measured benefit with sample size.

Rehearse network failure: retain the user's input, show a useful retry state, and introduce an accurately labeled previously recorded successful run if needed. Do not call a recorded run live.

## Likely judge questions

- Why does this need AI instead of fixed rules?
- How does it fit your assigned sub-theme?
- What happens when the model is wrong or unavailable?
- Which data is sent off the device, with what consent?
- What did your evaluation actually measure?
- What is original compared with existing tools?
- How can a reviewer run it and who will maintain it?
- What is the model's cost and what limits usage?

Use evidence and boundaries: "We measured X across N cases" is stronger than "This will help millions."
